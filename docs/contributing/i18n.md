# Internationalisation (i18n) guide

## Supported locales

| Code | Language | Status |
|------|----------|--------|
| `es` | Spanish (Argentine) | **Authoritative source** — all new strings are written here first |
| `en` | English | Translation — kept in sync with `es` |

Default locale on first visit: `es`. Stored in `localStorage` under the key `language` and preserved across sessions.

## Where translations live

All user-visible strings are in one file:

```
apps/web/lib/i18n-context.tsx
```

The file exports `I18nProvider` and `useI18n`. Every component that needs a translated string calls `const { t } = useI18n()` and passes the key: `t("sidebar.dashboard")`.

**Do not add inline string literals** to components for user-visible text. Every visible string must have a key in both `es` and `en` translation objects before the PR merges.

## Key naming convention

Keys follow a `<section>.<subsection>` pattern:

| Section prefix | Covers |
|----------------|--------|
| `landing.*` | Landing / marketing page |
| `dashboard.*` | Member dashboard |
| `certificates.*` | Certificate list and detail |
| `coopAdmin.*` | Cooperative admin panel |
| `superAdmin.*` | Platform super-admin panel |
| `activity.*` | Activity / transaction history |
| `consumption.*` | Generation history |
| `profile.*` | Profile page and modal |
| `wallet.*` | Wallet connection modal |
| `success.*` | Transaction success modal |
| `sidebar.*` | Navigation sidebar |
| `addMeter.*` | Add meter form |
| `submitReading.*` | Submit reading form |
| `createCert.*` | Create certificate form |
| `retire.*` | Retire certificate form |
| `registerCoop.*` | Register cooperative form |
| `onboarding.*` | Onboarding card |
| `common.*` | Shared labels (Back, Status, kWh, …) |
| `auth.*` | Login / auth page |

Use lowercase dot-separated names. No camelCase in key names.

## Adding a new string

1. Add the key to the `es` object first, with the Argentine Spanish value.
2. Add the same key to the `en` object directly below the last `en` key in the same section.
3. Use `t("your.key")` in the component.
4. Run the completeness check (see below) before opening a PR.

### Interpolated values

For strings with a runtime value, use `{n}` as the placeholder and replace it in the component:

```ts
// In translations:
"dashboard.timeMinutes": "Hace {n}m",

// In component:
t("dashboard.timeMinutes").replace("{n}", String(minutes))
```

## Completeness check

A script reports missing or extra keys across locales. Run it before every PR that touches `i18n-context.tsx` or any component file:

```bash
node scripts/check-i18n.mjs
```

The script exits non-zero when it finds missing keys in either locale or keys that appear in one locale but not the other. It also warns on any `t("…")` call site whose key is absent from the translation file.

Output format:

```
[MISSING in en] auth.loginTitle
[MISSING in es] auth.loginTitle
[UNUSED key]    legacy.oldKey
[UNKNOWN call]  components/foo.tsx:42  t("missing.key")
```

Fix all reported issues before merging. The script does **not** automatically add keys — contributors write the actual translation.

## Missing-key fallback behaviour

When `t(key)` is called and the key is absent from the active locale's translation object, the function returns the raw key string (e.g. `"auth.loginTitle"`). This is intentional during development so missing translations are immediately visible in the UI rather than silently blank. In production builds the completeness check gate prevents missing keys from reaching deployment.

## Translation ownership

| Locale | Owner |
|--------|-------|
| `es` | Core team (Argentine Spanish is the product's primary language) |
| `en` | Any contributor; core team reviews for consistency |

Changes to `es` strings that alter meaning (not just phrasing) require the same review as a product copy change.

## Locale switching

The `LanguageSelector` component in `apps/web/components/language-selector.tsx` renders a dropdown that calls `setLanguage("es" | "en")`. It is included in the sidebar and landing page header. No page reload is required — context re-renders all subscribed components immediately.
